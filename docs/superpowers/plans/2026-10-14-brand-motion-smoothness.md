# Brand, Motion & Smoothness — Plan (2026-10-14)

**User request:** "generate the logo and make it ready to use; add some normal animation so the app feels alive, not dead; make it smooth — sometimes it feels too heavy." Then: "think deep, plan a good plan, take the best idea and use the skills."
**Skills applied:** `frontend-design` (one bold moment, motion that answers an action, no generic fade-and-slide-up everywhere, brief-specific choices), `fixing-motion-performance` (transform/opacity only, no layout/blur on large surfaces, no unbounded loops, measure once, one animation system, no library migration), `planning-with-files`, accessibility (reduced motion).
**Subject / audience / job:** «تقويم أهل البيت» — Shia users composing a monthly wall-calendar poster; the job is: enter a month fast → get a print poster. The poster is the hero; the UI around it must be calm, fast and obviously responsive.

## 1. Diagnosis — why it "feels heavy" (evidence-first; track P measures)
- A poster is ~290 text-fitting widgets, each running a binary search of text layouts (+ a second unconstrained layout per candidate for the no-mid-word guard). Home renders one LIVE poster per draft card; the editor AppBar mini preview re-lays-out a full poster after every committed edit; Step 4 builds full posters per page.
- Fix order: (1) memoise FitText (identical results), (2) cached low-resolution raster thumbnails (Home cards + editor mini preview, debounced), (3) remove stray rebuilds (rows, pages), (4) only then animate — and never animate the live poster.

## 2. Brand (track L1 → L2)
- **Best idea:** trace the user's own calligraphy into TRUE vector paths (own tracer: marching squares + RDP + Bézier fit; no potrace/numpy here) → `BrandTitle`, `BrandMedallion`, `BrandMark` widgets crisp at any size; swap the five templates' raster logos for them (crisp at ×4/A3); ship a brand kit (`brand/svg`, `brand/png` 2048 px, README with colours/clear-space/min-size).
- **App icon (L2):** the emerald gold-ringed medallion (the brand's most recognisable shape at 29–48 px; a two-line calligraphic title inside a ring survives tiny sizes). Android adaptive (foreground medallion in the 66% safe zone on a deep-emerald background layer + monochrome layer for themed icons), iOS full set, web (192/512 + maskable), macOS, Windows .ico, Linux, favicon. Generated by a documented script/test from the SAME vector painter → consistent; no new packages.
- **Launch screens (L2):** native launch = flat emerald + centred medallion (Android 12+ splash theme, iOS LaunchScreen) so the Flutter splash can continue seamlessly from the same pixels.

## 3. Motion system (track A) — "alive, not busy"
**Principles:** (a) ONE orchestrated moment: the launch reveal; (b) every other motion answers a user action and shows what changed; (c) 160–260 ms, ease-out in / ease-in out, transform+opacity only; (d) nothing loops; (e) nothing animates a full-poster widget; (f) reduce-motion/`disableAnimations` → durations 0, no hero, no shimmer; (g) built-in Flutter animation only (no new packages); (h) no double-building of heavy subtrees during transitions.
**Tokens (lib/core/motion.dart):** durations instant 90 / quick 160 / base 240 / emphasised 360 / reveal 1100 ms; curves enter `easeOutCubic`, exit `easeInCubic`, emphasised `Cubic(0.05,0.7,0.1,1)`; `Motion.of(context)` returns scaled durations (0 when `MediaQuery.disableAnimations`); a global test switch `Motion.scale` (tests default to 0 via test/flutter_test_config.dart; motion tests set 1).
**Moments:**
1. **Launch reveal (the memorable moment):** continues the native splash: ring sweeps on (start top, clockwise→reading direction), calligraphy wipes right→left like a pen (a clip/gradient-mask wipe on the traced path, cached Path, transform-driven), ONE gold shimmer pass, then the medallion shrinks/moves into the Home header (hero) and the grid appears. Total ≤ 1.1 s; never blocks startup (plays while drafts load; if loading finishes early wait ≤ 1.1 s total; skip on warm resume and with reduce-motion).
2. **Home → Editor:** the card thumbnail (cached raster) Hero-flies to the editor mini preview; fade-through for the rest; back reverses. Delete: card fades/scales out (160 ms) then list reflows. FAB shrinks to icon on scroll-down, extends on scroll-up (built-in `isExtended`). Empty state: one-shot scale/fade-in of the illustration (no loop).
3. **Editor steps:** sequential fade-through (old out 90 ms → swap → new in 150 ms, 8 px shift in reading direction) so only ONE step subtree exists at a time (the day grid is heavy); stepper progress indicator slides via transform; save indicator morphs spinner → check (scale/fade); undo/redo cross-fades the mini preview image (raster).
4. **Day grid (shows what changed):** auto-fill / column shift / copy-previous-day flash the affected cells with a gold tint fading out over 600 ms (opacity on a tiny overlay, only on built rows); occasion chips fade in 120 ms (no size animation); validation count swaps with a short vertical slide.
5. **Template picker:** neighbouring pages scale 0.96→1 and fade slightly by page position (two pages only), chip strip auto-scroll `animateTo`, selected chip colour tween (tiny), name chip cross-fade.
6. **Export:** progress → success check "stamps" (scale-in 300 ms); failure → small horizontal shake (transform, 300 ms); success SnackBar unchanged.
**Forbidden:** blur animation, animating width/height/padding of large containers, Opacity widget around big subtrees (use FadeTransition inside a RepaintBoundary), infinite controllers (also keeps `pumpAndSettle` valid in tests), any animation inside poster templates.
